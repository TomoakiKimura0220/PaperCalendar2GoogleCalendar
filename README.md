# PaperCalendar2GoogleCalendar

Googleカレンダーを印刷して手書きのスケジュール帳として使い、書き込んだ予定をデジタルのGoogleカレンダーへ反映するための道具です。

MacBookで月間カレンダーの画像を読み取り、確認した予定だけを追加します。操作画面はMacBookのブラウザで開きます。画像の取得は手動です。

1. `run.command`を起動します。
2. 対象年月と画像を指定し、赤枠が日付のマスと一致するか確認します。
3. 解析結果を修正し、登録する予定を選びます。
4. Googleの既存予定と照合してから登録します。

初回は「起動」「APIの設定」を読んでください。認証情報がなくてもデモ画面を試せます。

## 起動

Python 3.11以降が必要です。ターミナルでこのフォルダに移動し、実行します。

```sh
./run.command
```

初回は必要なパッケージをインストールします。ブラウザが開かなければ http://localhost:8501 にアクセスしてください。終了はターミナルでControl+Cです。サーバーは127.0.0.1だけで待ち受けます。

## APIの設定

### YomiTokuで画像を解析する

YomiToku 0.15.1をCPUで実行します。APIキーは不要です。初回に公開モデルをダウンロードし、`data/models/`に保存します。画像はMac上で処理し、外部サービスへ送信しません。Googleカレンダーへの登録時は、選択して確認した予定の文字・日時をGoogleへ送ります。

日付はマスの位置から決め、対象月の最終日まで読み取ります。 初期設定では、不確かなマスと文字を検出できなかったマスを3倍に拡大して再認識します。モデルの評価値と文字量を比較して候補を選びますが、評価値は正答率ではありません。読みが異なる場合は、確認画面でマスを選ぶと両方の読みを表示します。速度を優先する場合は「不確かなマスを拡大して再認識」をオフにしてください。1マスの文字を1候補にまとめるため、複数の予定があるマスは確認画面で行を追加して分割してください。印刷文字と手書きの区別、取消線、矢印の意味は自動判定しません。時刻は明記された形式だけを抽出します。候補は初期状態で未選択です。


### Googleカレンダーに接続する

1. [Google公式のPythonクイックスタート](https://developers.google.com/workspace/calendar/api/quickstart/python)に沿ってGoogle Cloudプロジェクトを用意し、Calendar APIを有効にします。
2. OAuth同意画面を設定します。テスト公開の場合は、自分のGoogleアカウントをテストユーザーに追加します。
3. OAuthクライアントの種類に「デスクトップアプリ」を選び、認証情報のJSONをダウンロードします。
4. このフォルダの`secrets/client_secret.json`に保存します。
5. アプリで「Googleに接続」を押し、ブラウザでアクセスを許可します。
6. 登録先カレンダーIDを入力します。自分のメインカレンダーは`primary`です。専用カレンダーを使う場合は、Googleカレンダーの「設定と共有 → カレンダーの統合」からIDをコピーします。

OAuthはGoogleへのアクセス許可の仕組みです。許可した接続を再利用する認証トークンは`secrets/token.json`へ保存します。権限は予定の参照・編集に必要な`calendar.events`です。このアプリが実行する書き込みは予定の追加だけです。

認証が切れた場合は再接続してください。再接続できないときは`secrets/token.json`を削除して認証し直します。

## 固定レイアウト

日曜始まり、7列の月間カレンダーを扱います。初期のマス領域は、会話で添付された1174×904画像を基準にしています。画像の縦横サイズが変わっても比率で切り出します。

「固定レイアウトの調整」でマス領域の上下左右と週の行数を設定し、「レイアウトを保存」を押すと次回も使えます。必要な行数より少ない場合は解析を止めます。日付は対象年月とマス位置から計算し、AIが返した日付を採用しません。

写真では「写真の四隅を合わせる（台形補正）」を使います。初期設定の「自動検出」では、長い縦横の罫線を抽出し、横7列と指定した週数の並びから外枠を求めます。検出できない場合は「手動調整」に切り替えてください。紙の四隅ではなく、日付マス全体の左上・右上・右下・左下を指定してください。曜日の帯と余白は含めません。Xは画像の左端から、Yは上端からの位置を百分率で入力します。赤い四角を見ながら調整すると、補正後のマス位置にも反映されます。

会話で添付した手書き写真には「添付した写真の位置を初期値にする」ボタンが使えます。他の写真では位置を調整してください。補正を有効にすると、固定レイアウトの上下左右は使わず、四隅で囲んだ領域全体を7列と指定した週数に分割します。四隅を変更すると古い認識結果は無効になります。

自動検出は読み込んだ画像ごとに行います。検出後も赤枠の確認は必要です。紙の曲がりやたわみによる局所的なずれは残ります。解析前に赤枠と文字の位置を確認してください。週の行数が変わった場合も再調整が必要です。

## 確認と登録

`selected`にチェックした行が登録対象です。予定名・日付・時刻は表で修正できます。`text`は読み取った元の文字、`kind`は手書き・印刷・不明の判定、`issue`は確認事項です。AIの判定は誤ることがあるため、すべての行を未選択で表示します。

時刻は`HH:MM`で入力します。開始時刻が空なら終日、終了時刻だけ空なら開始から1時間です。補完後の値は「登録内容」で確認できます。明示した終了時刻が開始以前の場合は登録を止めます。時刻付きで複数日にまたがる予定はGoogleカレンダーで手動登録してください。

照合は指定した登録先カレンダーだけが対象です。祝日など別のカレンダーにある印刷済み予定は照合対象に入らないため、選択しないでください。

- 開始日時・終了日時・予定名が一致するものは「登録済み」としてスキップします。期間だけ違うものは「類似あり」として確認します。
- 同日に予定名か開始時刻が一致するものは「類似あり」としてスキップします。
- 表記が大きく違う予定は重複と判定できないことがあります。
- 登録直前にも再照合します。同じタイトルと開始日時から同じ予定IDを生成し、通信の再試行による二重登録を防ぎます。
- Google側で削除した予定を同じ内容で再登録するとIDが衝突する場合があります。その場合はGoogle側で手動登録してください。

一部の予定だけ登録できた場合は、結果を確認して再照合してください。登録履歴は`data/history.jsonl`へ1件ずつ保存します。既存予定の変更・削除、取り消し線の自動反映は行いません。

## マス内の両端矢印で期間を指定する

YomiTokuは文字を読み取りますが、両端矢印の開始日・最終日を自動解釈しません。確認画面の開始日と最終日を手動で指定してください。複数のマスに同じ予定の断片が出た場合は、1行にまとめてその行だけを選びます。終日の複数日予定は最終日を含めて登録します。

## 開発と検証

```sh
.venv/bin/python -m unittest discover -s tests -v
```

日付境界、複数日の終了日変換、週画像の連続性、期間不明時の登録防止、重複判定、GoogleカレンダーAPI応答の模擬テスト、デモ画面の起動を検証します。実際の手書き認識の精度とGoogleへの登録は、利用者の認証情報を設定して確認する必要があります。

主なファイルは`app.py`（画面）、`recognition.py`（画像解析）、`core.py`（日付と予定の検証）、`google_calendar.py`（認証・照合・登録）です。

問題が起きた場合は、画面のエラーと操作手順をこのCodexチャットへ伝えてください。APIキーや認証JSONの内容は貼り付けないでください。
